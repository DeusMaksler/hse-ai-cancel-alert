## О проекте

Отмена гостиничного бронирования осложняет планирование загрузки отеля. Мы оцениваем риск отмены **сразу после подтверждения брони**, используя только те сведения, которые известны в этот момент.


**Цель проекта** – разработать модель бинарной классификации и сервис, который по новой подтверждённой броне возвращает вероятность её последующей отмены.

### Что получится к концу года

| Результат | Описание |
|:---|:---|
| **Модель** | оценка риска отмены брони |
| **Сервис** | интерфейс для скоринга новой брони |
| **Сравнение** | линейная, нелинейная и нейросетевая модели |
| **Интерпретация** | факторы риска и анализ ошибок |

## Метрики качества

| Метрика | Зачем |
|:---|:---|
| **ROC-AUC** | общая разделяющая способность |
| **PR-AUC** | устойчивость при дисбалансе классов |
| **F1-score** | баланс точности и полноты |
| **Recall отмен** | сколько реальных отмен модель нашла |
| *Calibration curve / Brier score* | насколько вероятности правдивы |

## План работы на год

> На первое полугодие приходится около **70%** объёма работ.

### Первое полугодие

- [x] **ЧП1 · Старт и планирование** — `до 6 октября`
  Чат с куратором, установочный звонок, фиксация темы и плана работ, репозиторий с README.

- [ ] **ЧП2 · Разведочный анализ данных** — `до 27 октября`
  Пропуски, аномалии, распределения. Доля отмен, сравнение `city hotel` и `resort hotel`, связь отмены со сроком между бронированием и заездом, сезонность, тип депозита, специальные пожелания, новые против постоянных клиентов. Визуализация и выводы.

- [ ] **ЧП3 · Первые ML-модели** — `до 27 ноября`
  Выбор основной метрики. `DummyClassifier` как baseline, логистическая регрессия как линейная модель. Отсев признаков с утечкой, хронологическое разбиение. Подбор гиперпараметров, выводы.

- [ ] **ЧП4 · ML-сервис** — `до 15 декабря`
  Сервис на FastAPI: принимает данные, выполняет инференс модели, возвращает результат. Форма содержит только поля, доступные сразу после создания брони. На выходе – вероятность отмены и категория риска (низкий / средний / высокий) с обоснованием порогов. Тесты входных данных.
  > Этот чекпоинт является также домашним заданием по дисциплине "Инструменты разработки".

- [ ] **Промежуточная защита** — `10–15 января`
  Доклад о работе за семестр и планах на второе полугодие.

### Второе полугодие

- [ ] **ЧП5 · Улучшение ML-модели** — `до 15 марта`
  `CatBoostClassifier`, feature engineering, работа с дисбалансом классов, очистка данных. Задача – обойти baseline по выбранной метрике.

- [ ] **ЧП6 · Нейронные сети** — `до 5 мая`
  MLP на табличных признаках, сравнение с логистической регрессией и бустингом. Анализ не только итоговой метрики, но и качества вероятностей.

- [ ] **ЧП7 · Финальные доработки**
  MLflow и воспроизводимость экспериментов, переобучение и логирование лучшей модели, сохранение артефактов. Подбор бизнес-порога, калибровка вероятностей, SHAP, раздельный анализ двух типов отелей, анализ ошибок по `lead_time`, сезону и ценовому сегменту.

- [ ] **Итоговая защита** — `13–20 июня`
  Доклад о работе за год и результатах.
